## 手順

### 1. 完成物を観察して分割線を引く（講義・全員で）

前期サイトのスクリーンショットを見ながら「部品」に線を引いていく:

- `Header` — ロゴ＋グローバルナビ
- `ArticleCard` — サムネイル・カテゴリ・タイトル・日付のセット（**一覧で繰り返されている＝コンポーネント化の一番の候補**）
- `ArticleList` — ArticleCardを並べる枠
- `Sidebar` — プロフィール、人気記事など
- `Footer`

コンポーネントツリー（App → Header / ArticleList → ArticleCard×n / Sidebar / Footer）を先に紙に書いてから手を動かす。

### 2. 静的コンポーネントとして移植する

前期のHTMLをJSXにコピーして、まず**見た目だけ**再現する。CSSは前期のものをそのまま持ち込んでよい。

### 3. ArticleCardをpropsで汎用化する

ベタ書きの記事カードを `<ArticleCard title="..." category="..." date="..." />` の形にする。「同じ見た目・違う中身」がpropsの存在理由。

### 4. 記事データを配列にしてmapで表示する

```javascript
const articles = [
  { id: 1, title: "...", category: "...", date: "..." },
  ...
]
articles.map(article => <ArticleCard key={article.id} {...article} />)
```

「HTMLを10回コピペ」から「データ10件＋部品1個」への転換がこの回のハイライト。

### 5. stateで動きを足す

- ハンバーガーメニューの開閉（`useState` + クリックイベント）
- 余裕があれば: カテゴリボタンで記事の絞り込み（`filter` + state）

## 教えるポイント

- **分割の目安**: ①繰り返されている ②他のページでも使いそう ③責務がひとことで言える。逆に「分割しすぎ」も見せる（1行だけのコンポーネントは過剰）
- **HTML→JSXの罠**: `class`→`className`、`<img>`や`<br>`は閉じる（`<img />`）、`style="..."`はオブジェクトになる、コメントは `{/* */}`
- **propsは関数の引数と同じ**: 「データが上から下に流れる」だけ、というシンプルさを強調
- **mapとkey**: keyを付けないと出る警告を実際に見せて、なぜ必要かを説明
- **CSSの持ち込み方**: まずは前期CSSを1ファイルでimportでOK。CSS Modulesは「クラス名の衝突が起きてから」紹介すると動機づけになる
- **before/after比較**: 前期のHTML（コピペだらけ）とReact版（データ＋部品）を並べて見せ、「記事が増えたらどっちが楽か」を問いかける

## TypeScriptを意識した移行ステップ

静的移植の段階から「データに型を付ける」ことを意識すると、コンポーネント化の各手順がそのままTSの学習になる。

### TS-1. 記事の「型」を定義する（手順3のprops化の前に）

Xeoryの記事カードを観察して、含まれる情報を型に起こす:

```typescript
type Article = {
  id: number
  title: string
  category: string
  date: string
  thumbnail?: string // ない記事もあるなら ? を付ける
}
```

**「デザインを見て型を書く」＝情報設計そのもの**。カードに何の情報が載っているかを言語化する作業なので、デザイン志望の学生に一番刺さるポイント。

### TS-2. propsに型を付ける

```typescript
type ArticleCardProps = {
  article: Article
}

function ArticleCard({ article }: ArticleCardProps) {
  return <article>{article.title}</article>
}
```

### TS-3. データ配列に型を付ける

```typescript
const articles: Article[] = [
  { id: 1, title: "...", category: "...", date: "..." },
]
```

プロパティ名をわざとtypo（`title`→`titel`）して、**保存する前に赤線で気づける**体験をさせる。「型はデータと見た目のズレを検知する仕組み」という説明がここで腹落ちする。

### TS-4. stateは型推論に任せる

```typescript
const [isMenuOpen, setIsMenuOpen] = useState(false) // 型注釈なしでOK
```

初期値から型が推論されるので書かなくてよい。**「TSは全部書くものではなく、書かなくても守ってくれる」**例として見せる。

### 教えるポイント（TS編）

- 型は「データの設計図」。**先に型を書いてから中身を埋める**順にすると迷いにくい
- `?`（オプショナル）はデザインの「ある時だけ表示される要素」と1対1で対応する
- エラーメッセージを読む練習を意図的に入れる（typoさせて→読ませて→直させる）
- 詰まったら一時的に `any` で逃げてよい。ただし「逃げた場所」にコメントを残す約束にする
- この型定義は後のmicroCMS移行時に「APIレスポンスの型」としてほぼそのまま再利用できる——ここで書いた `Article` 型が後半戦の伏線になる
