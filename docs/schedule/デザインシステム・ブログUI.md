## この回でやること

デザインシステム／UIライブラリとは何かを知り、1つ選んで、ブログのUI（ヘッダー・記事カード・全体レイアウト）を作る。ここからは自分のブログのデザインを育てていく。

## 手順

### 1. デザインシステムとは何かを知る

デザインシステム＝色・余白・文字のルールを決めて、部品（コンポーネント）を再利用する仕組み。実在企業の例を見てイメージをつかむ:

- [デジタル庁デザインシステム](https://design.digital.go.jp/) — 行政サービスの統一ルール。日本語で読める本格的な実例
- [SmartHR Design System](https://smarthr.design/) — 日本企業の公開デザインシステムの代表例。文言ガイドラインまである

### 2. UIライブラリを見て回って、使うものを選ぶ

**授業では「完成品コンポーネント型」から選ぶ**（迷ったらMUIかAnt Design——情報量が多く、詰まったときに調べやすい）:

- [MUI](https://mui.com/) — GoogleのMaterial Designベース。実務での採用例が多い
- [Ant Design](https://ant.design/) — Alibaba発の大型デザインシステム。コンポーネント数が圧倒的
- [Chakra UI](https://chakra-ui.com/) — シンプルなAPIとアクセシビリティ重視
- [Mantine](https://mantine.dev/) — コンポーネント数が豊富でフック類も充実
- [HeroUI（旧NextUI）](https://www.heroui.com/) — Next.jsとの相性を意識したモダンな見た目
- [PrimeReact](https://primereact.org/) — テーマ切り替えが豊富な老舗ライブラリ
- [Radix Themes](https://www.radix-ui.com/) — アクセシビリティの土台に公式テーマを乗せたもの

参考（今回は使わないが知っておく）:

- [Tailwind CSS](https://tailwindcss.com/) — クラス名でスタイルを組み立てる方式。Next.js界隈の主流
- [shadcn/ui](https://ui.shadcn.com/) — Tailwindベースのコンポーネント集。コードをコピーして自分のものにする方式
- [daisyUI](https://daisyui.com/) — Tailwindにコンポーネントのクラスを足すもの

### 3. 選んだライブラリをNextプロジェクトに導入する

各ライブラリの公式ドキュメントの「Installation / Getting Started」に従って導入する。

### 4. ブログのUIを作る

ヘッダー・記事カード・全体レイアウトを、選んだライブラリのコンポーネントで組む。Xeoryのデザインは再現しなくてよい——新しい自分のブログとしてデザインする。

### 5. GitHubへpush

## 使いこなしのヒント

- 完成品型ライブラリのコツは「**ドキュメントを読んで、propsでカスタマイズする**」こと。困ったら公式ドキュメントの該当コンポーネントのページを開く癖をつける
- **テーマ設定**（色・フォントの一括変更）を最初に触っておくと、あとから全体の雰囲気を変えられる
- 用意された部品の範囲でデザインする「制約」も学びのうち。どのライブラリを選んでも、コンポーネントに分ける考え方はXeoryで学んだものと同じ

## 宿題

- 選んだライブラリでブログのトップページの見た目を整えてくる
