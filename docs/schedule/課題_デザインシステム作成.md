## この回でやること

自分のブログのデザインルールを、Figma上で「ミニデザインシステム」としてまとめる。ダークモード課題のCSS変数・4.4のタイポグラフィ・Storybookのカタログなど、**コード側に散らばっている自分のルールをデザイン側で言語化し直す**統合課題。Figma Variables ↔ CSS変数 ↔ Storybook が同じものの三面鏡になっていることを体感する。

本物のデザインシステムは巨大なので、**下のパーツリストの範囲に絞る**（ミニで完成させることが目的）。

## 作るもの一覧

### トークン（Figma Variables / Stylesで定義）

- **色**: 背景・テキスト・カード・ブランドカラー・エラー/成功。Variablesのモード機能で**ライト/ダークの両対応**にする（ダークモード課題で作ったCSS変数と1対1になるように）
- **タイポグラフィ**: 見出しL/M/S・本文・キャプションのスケール（4.4で選んだフォントを使う）
- **スペーシング**: 4か8の倍数で段階を決める
- **角丸・影**: 各2〜3段階

### コンポーネント（Auto Layout + Variantsで作る）

- **ボタン**: primary / secondary の2種 × 通常 / hover / disabled の状態
- **フォームパーツ**: テキスト入力（通常 / フォーカス / エラー）・ラベル・エラーメッセージ（お問い合わせフォームの実装とつながる）
- **ArticleCard**: サムネイルあり / なし（Reactで作ったpropsのバリエーションと同じ発想）
- **タグ / カテゴリバッジ**
- **トグルスイッチ**（太陽⇄月。ダークモード課題で実装したもののデザイン版）

### ドキュメント1ページ

色の使い分けルール・フォント選定の理由・ロゴの使い方を1ページにまとめる（SmartHRの文言ガイドラインのミニ版。「好みだから」ではなく理由を言葉にする）。

## 手順

### 1. 実物を観察する

デジタル庁・SmartHR（4.2参照）のデザインシステムをもう一度見て、「トークン→コンポーネント→ルール」という構造を確認する。Figmaコミュニティで公開されているデザインシステムのファイルを開いて、Variables・Variantsの作り方を覗く。

### 2. トークンを定義する

すでにコードにあるもの（CSS変数・フォント設定）をFigmaに写すところから始める。ゼロから決め直さない。

### 3. コンポーネントを作る

パーツリストの順（ボタン→フォーム→カード→バッジ→スイッチ）に、Auto LayoutとVariantsで組む。

### 4. ドキュメントページを書く

### 5. お互いのシステムを見せ合う

同じ構成で作っているので、トークンの選び方・コンポーネントの状態設計の違いが比較しやすい。

## 注意・ヒント

- **リストの範囲で完成させる**ことを優先する。項目を増やすより、ボタン1つの状態設計を丁寧に
- Figmaのコンポーネント/Variantsは、Reactのコンポーネント/propsと同じ考え方（「同じ見た目・違う中身」）。命名もコード側と揃えると後がきれい
- 作ったシステムは制作課題のデザインの土台や、Figma MCPでのコード化の題材としてそのまま使える
- 「自分のデザインシステム＋Storybook」はデザイン志望のポートフォリオとして強い成果物になる
