## この回でやること

React移行の締めとして、完成した静的React版XeoryサイトをVercelで公開し、push → 自動デプロイの流れを作る。あわせて環境変数の考え方を押さえ、後のmicroCMS編でAPIキーを安全に扱う準備をする。

## 手順

### 1. Vercelとは・GitHub連携での自動デプロイを知る

### 2. Vercelにプロジェクトを連携する

Viteプロジェクトは自動検出される（ビルドコマンド `npm run build`・出力先 `dist`）。

### 3. デプロイして公開URLを取得する

### 4. push → 自動デプロイの流れを確認する

手元で文言を1か所変えてpushし、公開サイトに反映されるまでの流れを確認する。

### 5. 環境変数とは何かを知る

`.env` と `.gitignore` の役割を理解する。**秘密の値をGitにコミットしない**。

### 6. 環境変数を手元とVercel側の両方に設定してみる

サイト名などの秘密でない値を `.env.local`（`VITE_SITE_NAME` など）に置いて `import.meta.env` から読み、同じ値をVercel側にも設定して再デプロイする。「手元は `.env.local`、本番はVercelの管理画面」という対応を体験する。

### 7. React編の振り返り

HTML/CSS → コンポーネント → 公開までの道のりを振り返る。

## Playwright MCPで確認

デプロイ直後に、本番の健康診断をAIにやらせる（→ [Playwright MCP実践](Playwright-MCP実践.md)）:

```
https://（自分の公開URL）を開いて、トップから辿れる全ページを巡回して。
リンク切れ・コンソールエラー・表示崩れがあれば、ページごとに一覧で報告して。
localhost では出ていなかった問題（画像が出ない・環境変数まわりのエラーなど）が
ないかも意識して見て。
```

## 注意・ヒント

- 「秘密の値はコードに書かない」は実務の鉄則。うっかりコミットした場合はキーの無効化・再発行が必要になるリスクがある
- Viteの `VITE_` 付き環境変数はビルド時にJSへ埋め込まれ、ブラウザから誰でも見られる。APIキーのような秘密はここに置かない。microCMSのAPIキーはNext.jsのサーバー側で読むので、この心配がない（microCMS編で再登場）
- push → 自動デプロイの体験は「Gitを使う理由」の答え合わせにもなる
