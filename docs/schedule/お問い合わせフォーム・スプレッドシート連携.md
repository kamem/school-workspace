## この回でやること

前回作ったフォームの送信先を作る。Google Apps Script（GAS）でスプレッドシートに追記するWebアプリを立て、Next.jsのServer Actionから送る。**「サーバーで動くコードを自分で書く」初めての回**——単位5で「サーバーでデータを読む」はやったので、今回は「サーバーで書く」。

## 全体像

```
ブラウザ（フォーム） → Server Action（Next.jsのサーバー） → GAS → スプレッドシート
```

ブラウザから直接GASに送らない理由: ①GASのURLを秘密にできる（環境変数） ②CORSの問題を踏まない ③サーバー側でもう一度検証できる。

## 手順

### 1. GAS側: 受け口を作る

1. スプレッドシートを新規作成 → 拡張機能 > Apps Script
2. `doPost(e)` を書く: `e.postData.contents` をJSON.parseして `appendRow` で1行追記（GASもJavaScript——習った文法がそのまま動く）
3. 「デプロイ > 新しいデプロイ > ウェブアプリ」でデプロイし、URLを控える

**デプロイの罠（初見殺し3つ）**:

- アクセスできるユーザーは「**全員**」にする（自分のみだと外から届かない）
- 承認画面で「このアプリは確認されていません」と出る → 詳細 > （安全ではないページに）移動 で進める
- **コードを修正したら再デプロイ（新バージョン）が必要**。保存だけでは反映されない

### 2. Server Actionを書く

`'use server'` の関数でフォームデータを受け取り、**前回と同じzodスキーマでサーバー側でも検証**してから、`fetch` でGASのURLにPOSTする。GASのURLは `.env.local` に置く。

クライアントの検証は開発者ツールで突破できる——だからサーバーでも同じスキーマを通す。スキーマを共有しているので追加コストはほぼゼロ。

### 3. 送信中・完了・失敗の状態を作る

`useActionState` で、送信中はボタンをdisabled＋ローディング表示 → 完了メッセージ / 失敗時の再試行案内を出す（スケルトン課題で学んだ「待ち時間のデザイン」の応用）。

### 4. デプロイして本番で確認する

VercelにGASのURLを環境変数として設定 → デプロイ → **公開URLから送信してスプレッドシートに1行増える**のを確認する。

## 注意・ヒント

- GASのURLはコミットしない（`.env` 管理の総復習。デプロイ回でやった流れと同じ）
- 学校のGoogleアカウントは「全員に公開」デプロイが管理者側で制限されている場合がある。**事前に講師＋学生アカウントで検証しておく**
- 失敗時のエラーはGAS側のログ（Apps Scriptの実行数）にも出る。届かないときはまずそこを見る
