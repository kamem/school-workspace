# 課題: 仕様から作るアプリ＋LP（料理アプリ・PWA）

- 日付: 未定
- 分類: React/Next.js
- 完了: [ ]

---

## この課題でやること

自分で決めた題材で「アプリ＋紹介用のLP」を作る。実装はAIにまかせてよい（バイブコーディング）。ただしその前に、**何を作るかを自分で決めて仕様書に書く**。仕様書はそのままAIへの指示書になる。

要件整理 → 仕様書 → デザイン → 実装 → PR を一周したら、分かったことで仕様書を更新して次の機能へ進む。実務でプロダクトが作られる流れを、数回の授業に分けて体験する。

題材は道具系のアプリなら自由（料理・筋トレ記録・植物の水やり・旅のしおり など）。迷ったら**料理アプリ**にする（このページの見本）。

## 作るもの

|        | 内容                                         |
| ------ | -------------------------------------------- |
| アプリ | 機能は3〜5個まで。スマホで使う前提           |
| LP     | アプリを紹介する1ページ                      |
| PWA    | ホーム画面に追加できて、オフラインでも開ける |
| 公開   | Vercelで公開する                             |

- 1つのNext.jsプロジェクトに、LP（`/`）とアプリの画面（料理アプリなら `/recipes`）の両方を置く
- データ（レシピなど）はJSONファイルに書いてプロジェクトに含めるか、端末（localStorage）に保存する。microCMSやサーバーは使わない

## 進め方

```
要件整理 → 仕様書 → デザイン → 実装 → PR・レビュー
              ↑                              │
              └──── 分かったことで仕様を更新 ←┘
```

| 回の目安 | やること                                        |
| -------- | ----------------------------------------------- |
| 1回目    | 要件整理・仕様書                                |
| 2回目    | Figmaでアプリの画面とLPのデザイン               |
| 3〜4回目 | 機能ごとに実装してPR・互いにレビュー            |
| 5回目    | PWA対応・LPの仕上げ・公開・仕様書を最終版にする |

## AIと作るときのルール

1. **動いたらすぐcommitする**。AIが別の場所を壊したときに、戻れる場所を作っておく
2. **APIキーやパスワードなどの秘密の値をAIに貼らない・コードに書かせない**
3. **AIの出力を採用するかは自分で決める**。何をAIに頼み、何を自分で決めたかをPRに書く

## 手順

### 1. 要件整理 — 誰の、どんな困りごとを解決するか

- 誰が・いつ・どこで使うかを1文で書く（例: 「平日に自炊する1人暮らしの学生が、冷蔵庫の残り物で夕飯を作るとき」）
- **先にLPの見出しとサブコピーを書いてみる**。アプリの価値を一言で言えないうちは、作る機能も決められない

### 2. 仕様書を書く

自分のリポジトリに `docs/spec.md` を作り、下の「仕様書テンプレート」を埋める。1ページに収める。

- 一番大事なのは「**作らないもの**」と「**完成の条件**」。AIは頼めばいくらでも機能を足すので、ここで線を引いておく
- 完成の条件は「〜すると〜になる」のように、触って確かめられる形で書く

書けたら、AIに抜けを質問させる:

```
docs/spec.md を読んで、実装を始める前に決めておくべきなのに
書かれていないことを、質問の形で5つ挙げてください。まだコードは書かないでください。
```

質問に答えて、仕様書に書き足す。

### 3. AIが仕様書を読むようにする

`.github/copilot-instructions.md` に次を足す（→ [Copilotカスタマイズ](Copilotカスタマイズ.md)）:

```
- 実装の前に docs/spec.md を読み、仕様に書かれていない機能は追加しない
- 仕様と違う実装が必要になったら、勝手に進めずに理由を説明して確認する
- 変更が終わったら、何を変えたかを説明する
```

### 4. Figmaでデザインする

- アプリの主な画面（料理アプリなら一覧・詳細）と、LPを作る
- デザインしていて決まっていないことに気づいたら、仕様書に戻って書き足す。**仕様書を直すのは失敗ではなく、普通のこと**

### 5. 機能ごとに実装する

仕様書の「完成の条件」の1項目を1つの単位にして進める。

1. ブランチを切る（例: `feature/serving-size`）
2. 仕様書の項目名を使ってAIに頼む（例: 「docs/spec.md の『人数を変えると分量が変わる』を実装して」）
3. ブラウザで動作確認し、動いたらcommitする

### 6. PRを作り、レビューし合う

PRの説明文は「何を・なぜ・どう確認したか」（→ [GitHub深掘り](GitHub深掘り.md)）に加えて、次の3つを書く:

- 仕様書のどの項目に対応するか
- 変更前後のスクリーンショット
- AIに頼んだことと、自分で決めたこと

3人で互いのPRをレビューする。コードだけでなく実際に触って、仕様書の「完成の条件」を満たしているかを確かめる。

### 7. 仕様書を更新する

実装やレビューで分かったこと（足した条件・やめた機能）を `docs/spec.md` に反映し、変更履歴に理由を残す。**実装と同じPRで仕様書も直す**と、あとから「なぜこうなったか」を追える。

### 8. PWA対応・LPの仕上げ・公開

- [PWA対応](PWA対応.md)の手順で、ホーム画面に追加できるようにする。manifestの `start_url` はLP（`/`）ではなくアプリの画面にする（ホーム画面から開いたら、すぐアプリが使えるように）
- オフラインでも開けるようにする（下のプロンプト）。データをアプリに含めているので、記事が毎日変わるブログよりも安全にキャッシュできる
- LPに実際のアプリ画面のスクリーンショットを入れて仕上げ、Vercelで公開する

```
このNext.jsプロジェクトにSerwistを導入して、オフラインでもアプリの画面を表示できるようにしてください。

要件:
- 対象はアプリの画面（/recipes 以下）と、そこで使うデータ・画像
- 開発サーバー（npm run dev）ではService Workerを無効にする
- 新しいバージョンをデプロイしたら、古いキャッシュが残り続けないようにする

最後に、オフラインで動くかを確認する手順を説明してください。
```

## 見本: 料理アプリの仕様書

```markdown
# のこりもの献立 仕様書

## 目的

- 誰の: 平日に自炊する1人暮らしの学生
- どんな困りごとを: 冷蔵庫に半端な食材が残るが、何を作ればいいか思いつかない
- どう解決する: 家にある材料からレシピを絞り込み、料理中もスマホで手順を見られるようにする

## LPの見出し

- 見出し: 冷蔵庫の「ちょっとだけ」が、今夜のごはんになる
- サブコピー: 材料を選ぶだけで、作れるレシピが見つかる。ホーム画面に入れて、キッチンでそのまま使える

## 作るもの（機能）

- 必須: レシピ一覧・詳細 / 材料で絞り込み / 人数を変えると分量が変わる
- 選択: 料理中に画面が消えない / お気に入り

## 作らないもの

- ログイン・ユーザー登録
- レシピの投稿・共有
- AIによる献立の自動提案
- 調理時間での並べ替え

## 画面

| 画面       | URL           | 内容                                 |
| ---------- | ------------- | ------------------------------------ |
| LP         | /             | アプリの紹介・ホーム画面への追加方法 |
| レシピ一覧 | /recipes      | 写真カードの一覧・材料で絞り込み     |
| レシピ詳細 | /recipes/[id] | 材料（人数を切り替えられる）・手順   |

## データ

レシピ1件: id / 名前 / 写真 / 調理時間 / 何人分 / 材料（名前・分量・単位） / 手順 / タグ

## 完成の条件

- [ ] 材料を2つ選ぶと、両方を使うレシピだけが表示される
- [ ] 2人分を4人分に変えると、材料の分量が2倍になる
- [ ] 「少々」「適量」は、人数を変えてもそのまま表示される
- [ ] ホーム画面に追加でき、アイコンから開くとレシピ一覧が表示される
- [ ] 機内モードでも、一度開いたレシピの詳細が表示される
- [ ] LPを見れば、ホーム画面に追加する方法が分かる

## 変更履歴

- 初版
- AIの質問「『少々』は人数を変えたらどうなりますか？」を受けて、完成の条件に追加
- デザイン中に調理時間で並べ替えたくなったが、時間内に終わらないため「作らないもの」に追加
```

## 注意・ヒント

- 機能を増やしたくなったら、まず仕様書の「作らないもの」と「完成の条件」を見直す。足すなら、仕様書を先に直してからAIに頼む
- **データの置き場所は用途で選ぶ**。ブログは記事をmicroCMS（サーバー）に置いたので、誰が見ても同じ記事が出る。このアプリはデータをアプリに含める・端末に保存するので、オフラインでも使える。どちらが正解ということはない
- レシピは自分の家の料理や自分で考えたものにする。料理サイトのレシピや写真を写すのは著作権の問題になる。写真も自分で撮る
- Service Workerは開発サーバーでは動かない設定にするので、オフラインの確認は `npm run build && npm start` か、Vercelにデプロイしてから行う
- 「料理中に画面が消えない」は Screen Wake Lock API で作れる（HTTPSが必要）
