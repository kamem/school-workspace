## この回でやること

ブログに `/contact` ページを作り、入力 → バリデーション → エラー表示までのフロントエンド側を完成させる。実務の定番構成（react-hook-form + zod）をここで体験する。送信先（サーバー・スプレッドシート）は次回。

## 手順

### 1. 実在サイトのフォームを観察する

エラーの出し方（いつ・どこに・どんな文言で）を見比べる。良いフォームと苛立つフォームの差を言葉にする。

### 2. `/contact` ページとフォームUIを組む

名前・メールアドレス・本文の3項目。デザインシステム回で選んだUIライブラリのフォーム部品（TextField等）を使う。

### 3. react-hook-formを導入する

`npm install react-hook-form` → `register` / `handleSubmit` の基本形。useStateで全部持つ方式との違い（入力のたびに再レンダリングしない・検証との連携が楽）を押さえる。

### 4. zodでスキーマを書く

```typescript
import { z } from "zod"

const contactSchema = z.object({
  name: z.string().min(1, "名前を入力してください"),
  email: z.string().email("メールアドレスの形式で入力してください"),
  message: z.string().min(10, "本文は10文字以上で入力してください"),
})

type ContactInput = z.infer<typeof contactSchema>
```

`zodResolver` でreact-hook-formに接続する。**`z.infer` でスキーマから型が生まれる**——「デザインから型を書く→型がCMSスキーマになる」ときた流れの続きで、今度は「検証ルールを書くと型がついてくる」。

### 5. エラーメッセージを表示する

各項目のそばに、「何をどう直せばいいか」がわかる文言で出す（文言もデザイン）。

### 6. 仮の送信処理を付ける

この回では `handleSubmit` の中身は `console.log` でよい。入力→検証→通ったデータがコンソールに出る、まで確認する。

### 7. Storybookに登録してpush

通常・エラー表示の状態をストーリーにする。

## 注意・ヒント

- `label` と入力欄を関連付ける（クリック範囲が広がり、スクリーンリーダーにも伝わる）
- バリデーションのルールはzodに一本化する（react-hook-form組み込みの `required` 等と混ぜない）
- ここで書いたzodスキーマは次回サーバー側でそのまま再利用する（伏線）

## AI導入用プロンプト（2段階）

環境構築と実装を分けて、1つずつ実行しては動作確認する。VS Code（Copilot）のエージェントモードに貼り付けて使う。

### プロンプト① 環境構築

```
このNext.jsブログにお問い合わせフォーム用のライブラリを導入し、実装の土台を作ってください。

要件:
1. react-hook-form / zod / @hookform/resolvers を dependencies に追加する
2. app/contact/page.tsx を作成し、見出しと空のフォーム（名前・メールアドレス・本文の
   3項目のUIだけ、バリデーションなし）を配置する
3. lib/contactSchema.ts を作成し、zodスキーマの置き場所だけ用意する
   （中身はこの後自分で書くので、空のz.objectでよい）
4. npm run dev で /contact が表示されることを確認する

最後に、導入した3つのパッケージがそれぞれ何をするものか
（react-hook-form＝フォームの状態管理 / zod＝検証ルールと型 /
@hookform/resolvers＝2つをつなぐ橋）を初心者向けに説明してください。
```

→ できたら確認: `/contact` が表示され、3項目のフォームが並んでいるか

### プロンプト② フォーム実装

zodスキーマ（手順4）を**自分で書いてから**使う:

```
app/contact/page.tsx のフォームに、react-hook-form と zod によるバリデーションを
実装してください。

要件:
1. lib/contactSchema.ts に自分が書いたzodスキーマを使う（スキーマは変更しない）
2. zodResolver でreact-hook-formに接続し、register / handleSubmit の基本形で組む
3. エラーメッセージは各入力欄のすぐ下に表示する
4. 送信時の処理は console.log(データ) でよい（送信先は次回作る）
5. label と入力欄を htmlFor / id で関連付ける
6. 未入力で送信 → エラー表示、正しく入力して送信 → コンソールにデータが出る、
   の両方を確認する

最後に、「入力 → register → handleSubmit → zodで検証 → 通ればonSubmit」という
データの流れを初心者向けに順を追って説明してください。
```

→ できたら確認: わざと空で送信してエラーが出るか、正しい入力でコンソールにデータが出るか

### プロンプトの使い方

- zodスキーマ（手順4）だけは自分の手で書く——検証ルールとエラー文言を考えるのがこの回の設計作業で、AIに渡すのはその「設計図」を実装に組み込む部分
- ②の説明パート（データの流れ）は復習教材としてREADMEに貼っておくとよい
